## Rulings (binding on implementers and reviewers)
- R1 (G1): Ruling: the three notes are copied byte for byte (sha256 equal to the source); the source, date and hashes go in a new `docs/v1-tools/README.md` — the plan's two sentences cannot both hold and the hash check is the stronger one — costs only a reader opening a note without the header (the README sits beside it).
- R2 (G2): Ruling: `TOOL_TABS` holds tool tabs only (design 8, collect 6, writing style and words, review 3, in the plan's order and ids). `PLACE_TABS.writing` is `["document", "style", "words"]`, the document tab being the frame's, prepended there — keeps `ToolTab.tool` as typed — costs nothing if wrong beyond moving one entry.
- R3 (G2): Ruling: tab labels (`tab_name_<tab>`, the existing pattern of `tab_name_find`) and "Suggested next" lines (draft §5) are frame strings and go through `V2_STRINGS` in `apps/web/scripts/i18n-overrides.mjs` like `tab_name_find`, with en.json and hi.json updated the way that file is used; Hindi is a draft marked as the overrides file marks drafts. Per-tool message files (G4) are for strings inside a tool's panel — tool sessions never touch frame strings — costs a move of ~40 keys if OJ wants them per tool.
- R4 (G2): Ruling: `Panel?: (p: { tab: string; projectId: string }) => React.JSX.Element` — the same type as written; React 19 has no global JSX namespace — costs nothing.
- R5 (G2): Ruling: tab → module: design's eight tabs → `design`; collect's data, power, charts, check, scales → `stats`, coding → `qual`; writing style → `style`, words → `words`; review closeness → `close`, viva → `viva`, slides → `slides`. A stage counts as built (home row, `BUILT_IN`) when any of its tabs' modules is built; Writing and the stage-2 stages stay built as today. `BUILT_IN` adds a tool id when its module is built (`viva` is not a `ToolId` and is skipped there) — costs a later session's home row reading wrong until fixed.
- R6 (G3): Ruling: the home reads a stage's blobs for `facts` only when one of its modules is built and declares `facts`, in a child component per such stage (hooks stay unconditional), so G's release adds no request — costs extra requests per built stage, accepted.
- R7 (G3): Ruling: `export type ExportDeps = ProjectExportDeps & { now: Date }`, exported from `apps/web/lib/export/projectExport.ts` (the name the plan uses, in the project export's module; the account export's `ExportDeps` in `lib/vault/export.ts` is untouched). Built-in parts keep their `ExportPart` union; module parts are `string` ids, listed after the built-in parts, with `openExport(preselect)` widened to accept them — costs a rename if a session needs more deps (it may extend through G only).
- R8 (G3): Ruling: a kind holding one v1 key holds that key's v1 value shape (`stats_sets` = `appu_statsets` {name: {hash, ts, n}}, `stats_runs`, `qual_codes`, `viva_log`, `words_bank`, `style_samples` arrays as v1; `design_*` as v1's objects). A kind merging several v1 keys is a loose object whose fields are the v1 key suffixes: `stats_prefs` {statsname?, gen_first?}, `qual_prefs` {showcolors?}, `words_prefs` {gram_stats?, spell?}, `close_prefs` {k?, min?}, `style_profile` {profile, on} (appu_style_profile, appu_style_on), `style_meta` = v1's meta object plus `vocab_level?` (appu_style_vocab_level). Objects loose, fields optional where v1 may lack them. Each session owns its `lib/blobs/kinds/<tool>.ts` afterwards and may tighten it — costs a session reshaping its own file.
- R9 (G4): Ruling: `text()` uses core's `docInnerText` (packages/core/src/doctext.ts:139, already v1's getEditorText for the helpers, lib/ai/actions.ts:128) on the editor's HTML — the plan's `docTextContent` does not exist — costs nothing.
- R10 (G4): Ruling: in a pop-out, `text()` and `selection()` stay synchronous by reading a mirror: the writing window posts `{type: "doc-snapshot", docId, text, selection}` on the sync channel when the editor changes (debounced) and when a pop-out says hello; the pop-out keeps the latest ("" before any). The async calls post a request with an id and await the writing window's reply; with no reply in 10 s they answer false / "no-selection" / [] and say `pop_nowin`. A pop-out never writes a document itself (D-S2-43) — costs a second round trip design if the mirror proves stale in practice.
- R11 (G4): Ruling: G4 also changes `apps/web/lib/editorExtensions.ts` so the editor keeps `data-run` and `data-qcode` on `span.stat-tag` / `span.qual-tag` (with a test that they survive a load and save), since otherwise the sanitizer change is undone by the editor — costs one more shared file in G.
- R12 (G4): Ruling: `rewriteDocument(id, html)` of the document open in the editor sets the editor's content (one undoable step) and lets its autosave store it; any other document is sealed and written through the existing document write path with a new revision. Test both — costs nothing.
- R13 (G4): Ruling: each `messages/tools/<tool>.hi.json` starts as `{ "$draft": "DRAFT: Hindi for Dr. Sharma's review, reviewed by: (pending)" }`; the merge skips `$`-prefixed keys; en files start `{}`. Every non-`$` key in a tool file that already exists in the base dictionary or another tool file throws — costs a marker format change.
- R14 (G4): Ruling: the tool files are imported statically from one module (`apps/web/messages/tools/index.ts` or in `lib/i18n.tsx`), and a test asserts every file in `messages/tools/` is in that list — costs nothing.
