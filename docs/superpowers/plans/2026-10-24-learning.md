# Learning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v1's Learning in v2, at v1 build 116:

- the lecture library and its player;
- device and natural voice;
- the practice questions;
- the theatre on desktop and phone;
- the practice-paper lesson and its question box.

Everything sits in its own `/learn` place, reached from the header and from every stage.

**Architecture:**

- **Core content.** A golden-harness engine runs v1 build 116 in jsdom. It emits Learning's content as JSON into `packages/core/src/data/learning/`: one index, plus one file per lecture, loaded on demand.
- **Core engines.** v1's Learning functions are ported close to verbatim as pure functions in `packages/core/src/learning/`, each held to v1 by a golden.
- **Web.** The place is a new `(app)/learn` route inside `ProjectShell` with no project. Progress is one sealed blob kind, `learn`, in the student's scratch project, and preferences are six `settings` keys.
- **Speech.** Natural voice goes through a new `POST /ai/speech` on the API.

**Tech Stack:** TypeScript, Next.js 16 (app router), React, Hono, zod, Vitest, Playwright, jsdom (golden harness), IndexedDB, Web Speech API.

**Spec:** `docs/superpowers/specs/2026-10-24-learning-design.md`. Read it first. OJ took its five recommendations on 24 October, as relayed by the main session: 1a, 2a, 3a, 4a, 5a. If OJ changes one, the main session will say which.

## Review Focus

1. **A student cancels the passphrase prompt in Learn, then answers questions and moves through slides, then unlocks.** Every answer and position given while locked is kept and merged with the stored ones; nothing stored is overwritten. Test in Task 4 ("held answers merge with stored ones after unlock").
2. **Learn is open in two tabs, and each answers a different lecture's questions.** Both sets of answers survive the blob's version conflict. Test in Task 4 ("two clients answering different lectures both keep their answers after a 409").
3. **A later re-pin changes a lecture's questions.** Stored answers by position would point at the wrong options. Those answers are dropped for that lecture only, and other lectures keep theirs. Test in Task 8 ("answers whose question hash changed are dropped, others kept").
4. **A browser with no speech, or no Hindi voice** (Firefox on Linux; an iPhone with Hindi chosen). Listen is disabled with v1's message, the player and theatre run on timers, and nothing throws. Test in Task 7 ("no speechSynthesis: Listen disabled, timers advance").
5. **The `from` link on `/learn?from=…` is built by the app, but anyone can type an address.** Only an in-app project path (`/p/<id>…`) is followed. Anything else gives no Back link. Test in Task 5 ("a from that is not an in-app project path gives no Back link").
