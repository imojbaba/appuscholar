# QA Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An automated QA suite that runs complete student stories on a production build of Appuscholar v2, checks each outcome as Data, Visual and Conceptual, and writes a report by story plus a fix brief.

**Architecture:** Playwright cases under `apps/web/qa/` run against `next start` and `node dist/index.js` on a test database. The test signs students in by minting the Auth.js session cookie. A test-only start-up script fakes the AI provider behind our API, and a browser-side router answers the outside services from recordings. A `qa` fixture gives every case typed checks, a watcher, layout rules and a result file, and a custom reporter turns the results into `qa-report/`.

**Tech Stack:** Playwright 1.64 (Chromium), TypeScript, Next.js 16 production build, Hono API built by tsup, Postgres 16 (CI) or pglite (Mac), `@axe-core/playwright`, `jszip`, `next-auth/jwt` `encode`, vitest 5 for the pure parts, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-24-qa-layer-design.md` (approved by OJ 2026-10-24). Read it first. Section numbers below (§n) are the spec's.

## Global Constraints

- No product code changes: nothing outside `apps/web/qa/`, `apps/web/test/qa/`, `.github/workflows/qa.yml`, `docs/qa/`, `apps/web/package.json` (scripts only) and `.gitignore` (the report folder). No new `data-testid`s. Locate controls with the existing test ids (as `apps/web/e2e/*.spec.ts` do) or by role and text; assert words against the dictionaries (`apps/web/messages/*.json`, `messages/tools/*.json`), never retyped.
- Test values only: generated passphrases, `@qa.test` addresses, keys `gsk_qa_<mode>_<random>`. Never a real credential; never the production site except the no-sign-in live check (§10.2).
- Every case has its own account (fresh uid and email), its own AI key suffix and its own downloads. Nothing is shared between cases.
- Expected numbers come from core functions or the core goldens on the same input (`packages/core/test/golden/**`), never retyped.
- Ports: API `QA_API_PORT` (default 8798), web `QA_WEB_PORT` (default 3010); `reuseExistingServer: false` always.
- Marks, exactly: `PASS`, `FAIL: UI`, `FAIL: Error`, `FAIL: Unexpected`, `FAIL: Slow`, `KNOWN FAULT`, `FIXED?`, `AWAITING DECISION`, `BLOCKED`, `NOT RUN` (§7). A check that measured nothing is `NOT CHECKED`, never a pass.
- Budgets (§8): progress sign within 1,000 ms; ordinary action within 10,000 ms; huge data within 30,000 ms; no main-thread freeze over 1,000 ms during huge data.
- Phone: 375 × 812, `isMobile: true`, `hasTouch: true`. Phone cases run in Hindi (§6).
- Case ids `S<story>-<nn>`, with the fault id in the title for regressions (`S6-02 [F3]`). Slice cases carry the tag `@slice`.
- Lint and typecheck clean (`pnpm -r lint`, `pnpm -r typecheck` cover `apps/web/qa/`).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A server left over from another run** answers on the QA ports, so the run tests old code. Expected: the run refuses to start when a QA port is taken and says which. Pinned in Task 1.
2. **A check that passes because it measured nothing** (a layout rule on an empty page, a Hindi rule that found no text, a zip with no entries). Expected: `NOT CHECKED` with the reason, listed under "Not covered". Pinned in Tasks 5 and 6.
3. **A case that passes only on its retry.** Expected: the report lists it under "Passed only on a second try"; it is never shown as a clean PASS. Pinned in Task 6.
4. **The live-AI key in a trace, screenshot or report.** Playwright traces record request bodies, which carry the key. Expected: live-AI cases run with traces off, and the reporter redacts the key's value anywhere it appears. Pinned in Tasks 6 and 17.
5. **Parallel cases crossing over:** one case's "fail once" key making another's request fail, or two cases sharing an email. Expected: the provider modes are per key, the accounts are per case, and nothing crosses. Pinned in Task 2.

**Interfaces:**
- Produces (`qa.ts`):
  - `type StoryId = "S0" | "S1" | "S2" | "S3" | "S4" | "S5" | "S6" | "S7" | "S8" | "S9" | "S10" | "S11" | "L"`

  - `type CheckKind = "data" | "visual" | "conceptual"`, `type FailKind = "ui" | "error" | "unexpected" | "slow"`

  - `interface Qa`:
    - `begin(meta: CaseMeta): void`
    - `step<T>(name: string, fn: () => Promise<T>): Promise<T>`
    - `check(kind: CheckKind, label: string, fn: () => Promise<void>, o?: { source?: string; known?: string }): Promise<boolean>`
    - `timed<T>(label: string, budgetMs: number, fn: () => Promise<T>, o?: { source?: string; known?: string }): Promise<T>`
    - `checkpoint(name: string, o?: { layout?: boolean; axe?: boolean; exempt?: string[] }): Promise<void>`
    - `allow(o: { hosts?: string[]; consoleErrors?: RegExp[]; statuses?: number[] }): void`
    - `expectDialog(type: "alert" | "confirm" | "prompt" | "beforeunload", accept: boolean): void`
    - `useKey(key: string): void` (the keys whose provider log belongs to this case; `newStudent` calls it)
    - `blocked(reason: string): never`
    - `selfTest: boolean` (selftests set it: no teardown throw) and `result(): CaseResult`
- Produces (`test.ts`): `test` (Playwright `test` extended with an auto fixture `qa: Qa`) and `expect`. Every case imports these.
- Produces (`known.ts`): `type KnownEntry = { id: string; title: string; status: "known" | "awaiting" | "fixed"; owner?: "OJ" | "Dr. Sharma"; match?: { rule?: string; text?: string } }`, `loadKnown(): KnownEntry[]`, `matchKnown(f: { rule?: string; text?: string }, known: KnownEntry[]): KnownEntry | undefined`.

Behaviour the tests pin:
- `step` names must be in `meta.steps`.
- When a step throws (not a check), the case ends there: `stoppedAt` holds the step, the page URL, a screenshot and the error. The steps after it are recorded as not reached, and the case's remaining planned checks are NOT CHECKED (§7).
- `check` catches its own failure (Playwright `expect` inside `fn`), records it, and returns false; the case continues.
- On teardown the fixture:
  1. attaches `qa-result` (JSON `CaseResult`);
  2. adds a `watcher` finding for every provider log entry of this case's keys with `outcome: "unknown"`;
  3. throws if any check failed that has no `known` id, or whose known entry has status `fixed`, so Playwright marks the case failed and CI goes red.
- The watcher (attached in the fixture) records Error findings for:
  - `pageerror`;
  - `console` errors not allowed;
  - responses of 500 or more from `QA_WEB_ORIGIN` or `QA_API_ORIGIN`, and 4xx not in `allow.statuses`;
  - requests to hosts other than localhost and `allow.hosts`;
  - dialogs not announced with `expectDialog` (they are dismissed);
  - `securitypolicyviolation` (an init script pushes them to `window.__qaCsp`);
  - a `load` of the main frame that no `qa`-initiated navigation explains: the fixture wraps `page.goto` and `page.reload` and counts the loads it expects.

  - a throwing step stops the case with `stoppedAt.step` set, and the later steps are listed as not reached;
  - `throw new Error()` in a page script gives a watcher finding of kind error;
  - `fetch("https://example.org")` in the page gives a watcher finding naming the host;
  - an unannounced `confirm()` gives a watcher finding, and an announced one does not;
  - a `timed` of 1,500 ms against a 1,000 ms budget gives `fail: "slow"`;
  - a failing check with `known: "F1"` (status known) does not fail the case;
  - the same check passing is recorded `ok: true` with `known: "F1"` (the reporter turns it into FIXED?).

### Task 5: Layout rules, accessibility and Hindi, at checkpoints

**Files:**
- Create: `apps/web/qa/support/layout.ts`, `apps/web/qa/selftest/layout.qa.ts`
- Modify: `apps/web/qa/support/qa.ts` (`checkpoint` calls it)

**Interfaces:**
- Produces: `type LayoutRule = "sideways-scroll" | "off-edge" | "cut-off" | "overlap" | "small-target" | "english-in-hindi" | "axe"`; `measureLayout(page: Page, o: { phone: boolean; lang: "en" | "hi"; exempt?: string[] }): Promise<{ findings: Array<{ rule: LayoutRule; target: string; detail: string }>; measured: Record<LayoutRule, number> }>`.
- `checkpoint` takes a full-page screenshot (attached and listed in `screenshots`). It records one visual check per rule: a finding is `fail: "ui"`, unless `matchKnown` gives an id; a rule whose `measured` count is 0 is `ok: null` (NOT CHECKED, Review Focus 2).

Rules (§8):
- sideways scroll: `scrollWidth > innerWidth`;
- off-edge: an element's box past the window's edge, unless an ancestor scrolls horizontally;
- cut-off: an element with overflow hidden or clip whose `scrollWidth` or `scrollHeight` exceeds its client size by more than 1 px, unless it has `text-overflow: ellipsis`;
- overlap: two visible enabled controls whose boxes intersect by more than 4 px;
- small target: on a phone, a visible control under 44 × 44 px;
- English in Hindi: Latin-script runs of two or more words of three or more letters, in visible text outside the editor (`.ProseMirror`), form fields and `exempt` test ids. - Produces:
  - `type Mark = "PASS" | "FAIL: UI" | "FAIL: Error" | "FAIL: Unexpected" | "FAIL: Slow" | "KNOWN FAULT" | "FIXED?" | "AWAITING DECISION" | "BLOCKED" | "NOT RUN"`

`markOf`, in this order:
1. any failed check (unknown, or known with status `fixed`) → `FAIL:` with the most severe kind, Error > Unexpected > UI > Slow;
2. `blocked` → BLOCKED;
3. a failed check with status `known` → KNOWN FAULT;
4. a passed check with a known id of status `known` → FIXED?;
5. any check with status `awaiting` → AWAITING DECISION;
6. otherwise PASS.

A case whose story is not built (`meta.story === "S4"` before Task 18) → NOT RUN.

The report (§12):
- **Header:** sha, date, kind, duration.
- **Summary:** one row per story with counts per mark.
- **Per story:** the goal, then per case its situation (in words), mark, failed checks (expected / happened / kind / source / screenshot / step), the stopped-at page, and the not-reached steps.
- **Screens:** a strip of each case's screenshots.
- **Passed only on a second try:** every case with `retries > 0`.
- **Not covered:** §2's non-goals as a fixed paragraph, NOT RUN stories, and every NOT CHECKED check.
- **Fix brief:** one entry per FAIL and per FIXED?, with the §13 fields. Its re-run command is `pnpm --filter @appuscholar/web qa:local -g "<case id>"`.

Every string passed in `redact` is replaced with `[redacted]` in all outputs.
