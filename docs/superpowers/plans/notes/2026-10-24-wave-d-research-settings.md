- Spoken punctuation, `dictFormat(t, lang)` (4257-4264). The phrase is trimmed and a space is put in front (`' '+t`) so a command at the start also matches. Every regex needs that leading space, removes it and leaves the trailing text. English list (flags `gi`, applied in this order): `/ (full stop)\b/` -> `.`; `/ comma\b/` -> `,`; `/ question mark\b/` -> `?`; `/ exclamation (mark|point)\b/` -> `!`; `/ colon\b/` -> `:`; `/ semicolon\b/` -> `;`; `/ new paragraph\b/` -> `\n\n`; `/ new line\b/` -> `\n`. Hindi list (flag `g` only, no `\b`): `/ पूर्ण ?विराम/` -> `।`; `/ अल्प ?विराम/` -> `,`; `/ प्रश्न ?चिह्न/` -> `?`; `/ नई पंक्ति/` -> `\n`. List chosen by `/^hi/.test(lang)`; every other code (en-IN, en-GB, en-US) uses English. Then `.replace(/\n[ \t]+/g,'\n')` and trim spaces/tabs at both ends. Not covered: period, dot, quote, brackets, Hindi exclamation/colon/semicolon/new paragraph.
- Auto-capitals and spacing, `dictInsert` (4265-4277): restore the saved selection; `prev` = text of the caret's text node before the caret (empty if the caret is not in a text node). Not Hindi: capitalise the first non-newline character when `!prev` or `/[.?!]\s*$/.test(prev)` or the phrase starts with a newline. Space rule: put one space first only if `prev && !/\s$/.test(prev) && !/^[.,?!:;।\n)]/.test(t)`. It inserts with `execCommand('insertText')`, adds no trailing space, and the text is untagged (not `ai-ins`; it is the student's own speech). The v1 spec note (01-workspace-and-writing.md 189-190) lists only some phrases and omits en-GB, "exclamation", "colon", "semicolon" and `प्रश्न चिह्न`.
- Strings: none of the dictation sentences are in `I18N.en` or `I18N.hi` (all hard-coded English). So there are no v1 keys and no v1 Hindi for the notice, the status line or the errors. Hindi exists only for the spoken commands above.

### 7b. How v2 stores things, and the recommendation
- Documents: server-side revisions, sealed under the document key when a vault exists (`lib/useAutosave.ts` `sealBody` 205-212; `Editor.tsx` `onSaved` fires when status is "saved"). Source documents have `kind === "source"` (`DocBar.tsx:32,144-153`). AI text is `span.ai-ins` (`packages/core/src/origin.ts` `walk`, exports `originCount`, `originShare`, `provHash`).
- Project blobs: one JSON per kind per project, `lib/blobs/useProjectBlob.ts` (debounce 800 ms, sealed with the vault, held when locked, `readOnly` in a pop-out for other stages via `blobWritable`). `apps/api/src/routes/blobWrite.ts:14-15` is the allow-list (`BLOB_KINDS`); the api never reads bodies, with the body cap `DEFAULT_MAX_BODY_BYTES = 2.8 MB` (`apps/api/src/app.ts:18`). A plaintext blob (keyVersion 0) is allowed only while the user has no vault record (`resolveBlobWrite`). The account export already writes every blob kind of every project (and the scratch space) as `<project>/stage-data/<kind>.json` (`lib/vault/export.ts:121-137`), and the account erase removes blobs with the project, so the "included in backups" and "erasable" requirements are met without extra code. Existing `style_samples` stores features only (the file comment cites v1 "never their text"), so it cannot hold these.
- **Recommendation: a new sealed project blob kind `writing_samples`**, one per project, shape `Record<docId, { title: string; text: string; words: number; updated: number }>` (v1 shape, with `title` sealed with the rest; a loose zod object like `lib/blobs/kinds/style.ts`). Do not use a setting (server settings are plaintext, unsealed, and a 2.8 MB cap would be wrong), and do not use `localStorage` (not per account, readable by any script on the origin, not in the export). It is stored with the project, locked by the vault like the documents, exported and erased with the project. Registration points for a new kind (all must change together, the tests fail otherwise):
  1. `apps/api/src/routes/blobWrite.ts:14` `BLOB_KINDS` (append `"writing_samples"`);
  2. `lib/blobs/kinds.ts:18-20` `BLOB_KINDS` (same string, same position), schema in a new `lib/blobs/kinds/samples.ts` (`SAMPLES_SCHEMAS`/`SamplesShapes`, imported and spread like `STYLE_SCHEMAS` at ~lines 4-9 and ~86), plus the `FixedShapes` intersection (~line 78);
  3. `lib/frame/stages.ts:39` `KIND_STAGE`: `writing_samples: { stage: "writing", work: false }` (a derived copy must not make Writing "in progress" by itself);
  4. `lib/blobs/useProjectBlob.ts:12-13` `UNGUARDED` (add it: a toggle/capture should not prompt "save over an unreadable blob?" the way work does; the capture is rebuildable);
  5. tests that pin the list: `test/frameStages.test.ts:15-26` (`want` + `BLOB_KINDS.slice(9)`), `apps/api/test/blobs.routes.test.ts:15-18,42` (`NEW_KINDS`), `test/useProjectBlob.test.tsx:~146` (kind list) and ~218 (round-trip sample).
