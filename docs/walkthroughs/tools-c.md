# Tools C walk-through: Coding (qualitative coding)

Definition of done for session C of the stages 3 to 6 tools plan (`docs/superpowers/plans/2026-10-21-stages-3-6-tools.md`): in Collection and analysis, the **Coding** tab lets a student build a tree of their own codes, tag passages of their document with them, see the tags drawn in the code's colour, list every passage of a code across their documents, export the coded passages, and delete a code without losing any words. It uses no AI: coding is the student's own judgment. A student meets all of it on the live site. Tests passing is necessary, not sufficient.
Walked by OJ, in Chrome, on the live site. The same journey runs automatically in `apps/web/e2e/tools-c.spec.ts`; rows 1 to 10 carry that spec's step numbers (the spec runs on a local copy of the app, with the vault turned on in its step 6). Rows 0 and 11 to 13 are this sheet's alone. Keep the two in step.

**Site:** https://appuscholar-web.vercel.app
**You need:**
- **An account with a project** whose idea is saved (the walk account from wave B1 will do), signed in, with the vault passphrase if the vault is on. The project should have no codes yet; if it has, add the new ones below the old and read the counts to match.
- **A desktop browser** at about 1440 px wide, and the browser's device mode at 375 px wide (row 10).
- A few lines of text of your own to tag, for example an interview answer. Two documents are needed from row 7 on.
